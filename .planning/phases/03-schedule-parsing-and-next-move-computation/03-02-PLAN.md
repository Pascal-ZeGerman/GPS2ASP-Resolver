Follow project conventions: `from __future__ import annotations`, frozen dataclasses, `logging.getLogger("gps2asp.schedule.{module}")`.

**merge.py** -- Window merging for multi-sign blocks.

1. `merge_windows(windows: list[TimeWindow]) -> WeeklySchedule` -- Takes flat list of TimeWindow from all parsed signs, returns a WeeklySchedule with merged, non-overlapping windows.
   - Group windows by day (ASPDay).
   - For each day, sort by start_time.
   - Merge overlapping/adjacent windows per user decision: if window B's start_time <= window A's end_time, merge into (min(starts), max(ends)). Concatenate source_sign lists from both.
   - Conservative: earliest start, latest end (user locked decision -- safer for avoiding tickets).
   - Return WeeklySchedule with all merged windows sorted by day then start_time.
   - Handle empty input: return WeeklySchedule with empty tuple.

**next_move.py** -- Timezone-aware next-occurrence computation.

All datetime operations use `zoneinfo.ZoneInfo("America/New_York")` for timezone awareness. Define `NYC_TZ = ZoneInfo("America/New_York")` module-level constant.

1. `find_active_window(schedule: WeeklySchedule, now: datetime | None = None) -> CleaningWindow | None` -- Check if `now` falls inside any ASP window.
   - If now is None, default to `datetime.now(NYC_TZ)`. If naive, attach NYC_TZ.
   - Check today's weekday. For each window on that day, check if start_time <= now.time() < end_time.
   - If match, return a CleaningWindow with concrete datetimes (combine today's date with window times).
   - Return None if not currently inside any window.

2. `find_next_window(schedule: WeeklySchedule, now: datetime | None = None) -> CleaningWindow | None` -- Find the next upcoming ASP window.
   - If now is None, default to `datetime.now(NYC_TZ)`. If naive, attach NYC_TZ.
   - Look ahead up to 7 days (8 iterations: today through 7 days from now, per user decision).
   - For day_offset in range(8): compute candidate_date, get weekday, iterate windows_for_day.
   - For each window: combine candidate_date + window.start_time as timezone-aware datetime.
   - If window_start > now, return CleaningWindow with filled start_datetime and end_datetime.
   - Return None if no window found (should not happen with weekly schedule + 7-day lookahead, but handle gracefully).
   - All datetime.combine calls use `tzinfo=NYC_TZ` parameter to ensure timezone awareness.

**summary.py** -- Human-readable schedule summary.

1. `format_summary(schedule: WeeklySchedule) -> str` -- Generate a compact string like "TUE & FRI 11:30 AM - 1:00 PM" or "MON-FRI 8:00 - 9:30 AM".
   - Group windows by (start_time, end_time) tuple -- windows with same times on different days are grouped.
   - For each group: format days as abbreviated names (MON, TUE, WED, THU, FRI, SAT, SUN).
     - If consecutive days form a range of 3+, use dash notation (MON-FRI).
     - If 2 days, use ampersand (TUE & FRI).
     - If 1 day, just the name (TUE).
   - Format time range: "8:30 AM - 10:00 AM". Use 12-hour format. Omit minutes if :00 (e.g., "8 AM" not "8:00 AM"). Simplify same-meridiem: "8:30 - 10:00 AM" (omit AM on start if both are AM).
   - Join multiple groups with " / " separator (rare: most blocks have one time pattern).
   - Return the string. If schedule is empty, return "No schedule".

   - If `isinstance(sign_result, NoASPSigns)`: return `NoASPSchedule(status="no_asp")`.

   - If `isinstance(sign_result, SignRetrievalSuccess)`:
     - Parse each sign via `parse_sign(sign.sign_description)`.
     - Collect all TimeWindow results (flat list) and ParseFailure objects.
     - If no windows parsed (all failed): return `AllUnparseable(status="all_unparseable", parse_failures=failures)`.

     - Otherwise: find next window via `find_next_window(merged_schedule, now)`.
