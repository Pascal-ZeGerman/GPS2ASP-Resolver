Create `scripts/geocode_fixtures.py` -- a standalone CLI script that geocodes NYC street addresses into GPS fixture JSON files. Must be reusable for Phase 17 (Manhattan).

Script structure:
1. Use `httpx.Client` (sync, not async -- this is a one-time batch script)
2. Endpoint: `https://geosearch.planninglabs.nyc/v2/search` (CRITICAL: v1 returns HTTP 410)
3. For each address: `GET ?text=<address>&size=1`
4. Extract `features[0].geometry.coordinates` -- GeoJSON is `[lon, lat]` (lon index 0, lat index 1)
5. Verify `features[0].properties.borough == "Queens"` (or expected borough)
6. Output format: `[{"description": "<label from API>", "lat": <float>, "lon": <float>}]`
7. Add 0.5s sleep between requests (courtesy delay)
8. Handle failures: log warning, skip address, continue
9. CLI: `python scripts/geocode_fixtures.py --borough queens --output tests/fixtures/queens_coverage.json`
10. Also support `--borough manhattan` (different address list) for Phase 17 reuse

3. Print diagnostic block showing:
   - CSCL sent: `from={normalize_to_soda(cscl_from)}`, `to={normalize_to_soda(cscl_to)}`

Implementation details:
1. Add `async def diagnose_l3(on_street, side, cscl_from, cscl_to)` function that:
   - Creates `SODAClient()` instance
   - Calls `build_on_street_query(normalize_to_soda(on_street), side)` then `fetch_signs()`
   - Extracts unique `(record["from_street"], record["to_street"])` spans with counts
   - Returns a list of `{"from": f, "to": t, "count": n}` dicts, sorted alphabetically
2. Modify `audit_fixture()` to accept a `verbose: bool = False` parameter
3. When verbose and soda_level >= 3 or status != "ok": call `diagnose_l3()` and store diagnostic data in the result dict under key `"l3_diag"`

   ```
                 from='STREET C'  to='STREET D'  (8 signs)
   ```
